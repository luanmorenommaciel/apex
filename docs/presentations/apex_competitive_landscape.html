Sparklens (Qubole) · Dr. Elephant (LinkedIn)
Profilers post-mortem
clássicos
Leem o event log, calculam eficiência de executor, detectam skew, sugerem configs. Provam que análise de event log funciona — o mesmo caminho que escolhemos. Limitação: heurística fixa, sem motor extensível, sem agente. Confirmado sem manutenção desde jul/2021.
sparkMeasure (Luca Canali · CERN)
Biblioteca de métricas
via Listener
Coleta TaskMetrics e StageMetrics em tempo real via SparkListener. OSS, mantido, zero recomendação — só coleta. É a referência de implementação de listener não-intrusivo que usamos como base. Validou a abordagem de coleta; não é um produto de recomendação.
O que eles deixaram aberto
Os dois param na observabilidade. Nenhum conecta o sinal do log com o repositório de código, com um agente com KB especializado, ou com um ciclo de feedback sobre o PR. Essa lacuna é exatamente o que o Luan quer fechar.
O competidor mais próximo · tese idêntica, caminho diferente

DataFlint: mesma tese,
escolhas distintas.

DataFlint OSS · Apache-2.0
Plugin no driver + History Server
Roda como spark.plugins dentro do cluster. UI enriquecida, bottleneck detection, planos visuais. Mais intrusivo que o nosso event-log tail — requer deploy no cluster, viola a premissa de adoção voluntária de clientes grandes.
DataFlint SaaS · IA via MCP
Copiloto proprietário com LLM
Comprime logs 100×, envia via MCP pra OpenAI/Gemini/Claude. IDE copilot, fleet observability, cost. Chasing the same agentic world — validam a tese. Limitação: IA é SaaS proprietário, não auto-hospedável, e não é agnóstico de fornecedor. Sem cross-job memory ou feedback loops.
A diferenciação do Apex
DataFlint chega perto mas divide em dois produtos: o OSS (coleta) e o SaaS (inteligência). O Apex é um único sistema OSS onde coleta e inteligência e acesso ao código convivem. E a coleta é mais não-intrusiva (event-log tail, nenhum JAR no cluster).

A justificativa · por que a abordagem do Gabriel é a escolha certa

Não é preguiça.
É posicionamento.

Augusto sentiu que adotar o trabalho do Gabriel como proposta principal "parecia preguiça". O mapa diz o contrário: a abordagem event-log-first do Gabriel posiciona o Apex exatamente no quadrante que está vazio — e que todos os outros tentaram mas não conseguiram ocupar.

O que a abordagem do Gabriel entrega
Event-log-first (sem JAR no cluster) + Listener async Day 1 + tail out-of-process Sprint 2 (serverless) + ClickHouse como store. É o substrato de coleta que honra a premissa não-intrusiva que nenhum dos comerciais honra.
Por que os outros não estão nesse quadrante
Sparklens/Dr.Elephant: chegaram lá mas morreram.
DataFlint OSS: plugin (intrusivo) + IA é SaaS proprietário.
Unravel: chega na capacidade mas com agente pesado.
Overwatch: só Databricks.
A diferenciação que ninguém tem ainda
Cross-job memory e feedback loops — Apex aprende entre jobs. A Unravel diz que tem isso num knowledge graph proprietário de décadas. O Apex faz open, com KB auditável, e com o Judge adversarial pra evitar alucinação. Isso não tem preço de mercado ainda. É o que o time está construindo.
