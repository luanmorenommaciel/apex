## P7.2: different status meanings before findings were persisted

Before the Engine persisted findings for that same job, API diagnosis reported `degraded` from observed, unadjudicated symptoms. The Console displayed `HEALTHY` because its rollup had zero persisted findings. [Before](evidence/l7-20261028/pre-engine-console.png) and [after](evidence/l7-20261028/post-engine-console.png) show the Console transition to `DEGRADED` once four findings were persisted. The [parity summary](evidence/l7-20261028/parity-summary.json) records the API side.

These labels currently answer different questions. The API symptoms have `adjudicated=false`; the Front's rule evaluation also depends on measured slots. A gate that compares only the words `HEALTHY` and `degraded` would be misleading. This observation informs the team's P7.2 decision but does not choose option A or B.

## Limits and next acceptance

- The tested integration tree was local and disposable, not the final SHA of an official PR. The green checks on individual PRs do not replace a gate on the chosen combined tree.
- Ask was `SCRIPTED`; it was not tested as an LLM diagnostic conversation. Memory and Verify showed empty states because their relevant records were absent.
- This was one single-worker local Spark run and one controlled API outage. It does not cover all retries, thresholds, latency, authorization, or production behavior.
- Claude, Gemini, and Kimi reviewed the protocol and inferences before execution; they did not run this VM or browser session. The observations above come from the local test artifacts.
- The full JSON payloads and raw runtime logs are retained locally for private inspection. Public summaries expose counts, statuses, canonical hash, assertions, and captures while avoiding the complete local diagnostic record.

**Acceptance sequence:** agree on P7.2 status and verdict semantics and the official integration order; then repeat the verdict assertions and browser route on that exact SHA. Ask (P7.11) and `apex-mcp-http` (P7.14) remain separate team decisions. This document does not approve or merge another person's PR.
